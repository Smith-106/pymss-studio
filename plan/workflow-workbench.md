# 工作流功能独立计划

## 目标与最终边界

将原先在分离页使用的工作流运行功能迁到工作流模块，保留原有页面结构、独立系统弹窗、简易及高级编辑器的操作习惯。

- 分离页保留单模型分离和快捷 Ensemble。
- 工作流管理页沿用原有列表、筛选、详情、导入导出和管理操作；每种工作流保留一个对应编辑器入口。
- 简易和高级分别打开原有独立系统编辑窗口。简易自动保存，高级沿用原保存操作；在窗口内运行后继续保持打开。
- 简易工作流由 Studio 提供本次文件/目录选择、输出绑定及逐文件批处理。
- 高级工作流直接使用 pymss graph 原生节点、路径字段、参数、目录批量加载和保存规则。移除 Studio 的统一绑定抽屉、输入槽重写、逐文件任务拆分和逐节点输出目录覆盖。
- 运行时允许继续编辑。任务使用提交时的快照，后续编辑用于下次运行；主窗口继续负责现有队列、取消和历史。
- 简易输入与绝对输出根目录保存在运行会话；高级文件路径、输入目录和保存子目录按原生 graph 字段保存及导出。

## 用户确认的实施步骤

1. 以 `467e971` 为 UI 基线，恢复两个编辑器的窗口容器、工具栏、参数区、画布和页脚布局，保留窗口拖动、最大化、还原和关闭。
2. 分离页移除工作流选择及运行入口，保留单模型和快捷 Ensemble。兼容旧持久化模式，避免旧工作流模式使单模型页面不可用。
3. 工作流管理页保持原结构，保留原样式的“编辑步骤”或“编辑节点图”入口，进入相应编辑器完成编辑和运行。
4. 两个主画布保持单实例。运行、查看结果和查看提交快照不能销毁主画布，也不能清空历史、视角或选中状态。
5. 简易输入节点直接显示文件列表，汇总保存节点通过齿轮打开本次输出设置弹窗。高级恢复原生节点路径字段，文件/目录按钮只负责填入该字段，不引入独立绑定界面。
6. 简易移除底部操作栏，名称点击后编辑，描述在管理页维护。顶部只保留撤销/重做、添加步骤、适应视图、设置及运行；默认参数与自动布局收进工作流设置弹窗，简易自动保存。高级继续在原工具栏保存旁提供运行并保留关闭。请求交给主窗口，编辑器持续开放编辑。
7. 原操作区显示紧凑状态和整体流程进度，节点下方可折叠查看本节点日志。运行详情使用日志、节点执行和结果标签弹窗，不再嵌套流程编辑器。处理定义改变后不把旧任务进度标到新流程上。
8. 验证原有交互、原生 graph 参数、两种模式的输入输出行为、快照、重试、取消及导入导出，完成构建和最终 review 后交由用户验收。

此前原型的顶部运行面板、当前流程/本次执行切换、画布替换及高级统一绑定方案已经被当前方案取代。

## 简易工作流运行契约

- 工作流定义保存节点、连线、模型、处理参数、格式、命名和布局。本次文件与绝对输出根目录不写入定义或导出文件。
- 输入文件夹沿用 Studio 媒体扫描器，形成冻结的文件列表；每个文件完整执行一次流程。
- 汇总保存节点使用一个本次根目录，在提交时展开为所有保存音轨的目标目录；新增保存音轨继续使用该根目录。
- 默认目录在提交时解析并冻结。沿用私有临时目录、最终输出发布和原子重名保护。
- 原有逐音轨保存开关、文件命名、连线和输入输出端口保留。
- 运行绑定独立于撤销历史和 dirty 状态，应用重启后重新选择；已提交任务的路径和快照保存在历史中。
- 简易编辑窗口关闭后再次打开时，输入文件和输入目录选择清空。主窗口的运行会话恢复不覆盖新窗口的输入列表；首次自动保存分配工作流 ID 及重新聚焦已打开的窗口均保留当前选择。正在运行及历史任务继续使用原有冻结的输入快照。

## 高级工作流运行契约

- `pymss_load_audio` 使用原生单文件路径；`pymss_load_audio_batch` 使用原生目录、递归和排序字段。
- 文件/目录选择调用已有系统对话框，只更新原节点路径。明确选择磁盘路径时清空该节点的可选 `input_name`，由 SDK 直接读取路径。
- 原有路径文本字段保留，可编辑；额外选择按钮不参与序列化。撤销重做使用原 graph 历史，恢复节点后重新安装按钮。
- 输出根目录使用 Studio 设置中的默认输出目录，在提交时冻结。`pymss_save_audio.output_folder` 继续是该根目录下的原生子目录，不作为绝对输出目录选择器。
- 高级任务作为一个完整 graph 提交一次。请求不携带 Studio `workbench`、`inputs`、`workbenchOutputs` 或逐文件 `tasks` 覆盖。
- 来源 graph JSON 直接进入任务配置，不使用 Studio 的输入槽重命名、路径清空、输出改写或节点默认参数补齐。执行使用现有 `load_comfy_file()` / `run_dag()`。
- SDK 负责目录扫描、列表数据流、处理和保存。多个原生目录节点遵循 SDK 行为，不套用 Studio 的主输入及文件配对限制。
- 目录内容在实际执行时由 SDK 扫描；冻结的是 graph 中的目录路径和参数，不是目录文件清单。
- 任务仍记录来源定义、版本和输出根目录，供进度、只读快照及重试使用；这部分是任务元数据，不改写 graph 的处理逻辑。
- 新高级快照通过 `nativeGraph` 标识保持原生重试语义。旧历史任务保留原有运行协议，避免改变已有记录的输入输出目标。

## 共用编辑器与生命周期

- 有修改时保存捕获的流程版本再提交；版本冲突不启动任务。异步保存期间的新编辑不覆盖已捕获的运行版本。
- 当前处理定义匹配提交快照时显示节点进度。简易额外要求运行绑定匹配；高级不依赖 Studio 绑定。视角、位置和颜色等外观变化不影响匹配。
- 运行详情的节点执行列表读取提交时的定义、状态和日志，不创建第二个编辑器。已修改当前流程时，通过该列表查看旧任务的节点执行情况。
- 主窗口负责运行、取消、重试及历史写入，弹窗通过现有桥接接收回执与任务镜像。关闭弹窗不取消任务，终态不被迟到进度覆盖。
- 主窗口旧编辑器地址交给独立弹窗处理，主窗口保留工作流管理页；打开失败保留可用页面。

## 编辑窗口归属与共享状态审查

- 原生窗口按正式工作流 ID 唯一，简易和高级入口复用同一工作流的已有窗口。首次自动保存、另存副本在落盘时同步更新归属，窗口标签保持固定；另存副本后原工作流可以独立打开。
- 后端登记完整窗口列表并发布带 revision 的快照，主窗口忽略乱序事件。管理页按各工作流归属锁定修改；关闭一个窗口只释放其记录，重复关闭通知不解除其他工作流的锁定。
- 开窗查找与创建串行化，构建和聚焦期间不持有注册表同步锁。每个原生工作流标签在进程内只使用一次，避免旧 Destroyed 事件误释放立即重开的新窗口。
- 保存和删除在后端校验调用窗口的归属，强制保存不能绕过。禁止通过通用 app store 接口整库覆盖工作流；版本冲突保留为外部修改的恢复机制。
- 简易冲突副本保留当前名称、草稿和本窗口输入设置。高级编辑器拒绝找不到的明确工作流 ID，冲突副本及覆盖保存读取当前画布，提交期间暂缓手动保存，关闭前等待提交完成。
- 音频项目重复打开仅聚焦已有窗口，不重载磁盘项目；项目加载请求串行并跳过当前 ID，切换时先保存当前项目。迟到的事件订阅在视图销毁后立即清理。项目目录和窗口入口统一校验 ID，拒绝路径特殊项和清洗、截断、尾点造成的别名，保留正常生成 ID 的目录。
