2. 第七轮（04cde28）发现并修复的流程遗漏

A. 删除最后一个插件后，播放按钮可能永久处于 pausing。
原因：两个宿主切换 watcher 都更新 requestId，迟到的原生暂停响应被当作过期响应丢弃。
修复：离开原生图时保留暂停请求的身份，等待其结算后再允许 Web Audio 播放。
回归覆盖实际播放组合层与 playback store，而非仅检查独立 native adapter。

B. 导出准备期间修改插件、Undo 或重新定位，可能混合旧混音与新插件状态。
原因：导出先复制项目，再等待捕获，之后仅按 slot ID 向旧副本拷入新 state。
修复：状态捕获后一次性冻结原项目的完整状态；切换项目不混入新项目，取消不启动渲染。
冻结语义为“捕获完成时”，并重新校验格式和内置效果限制。后续渲染和编码固定使用该快照。

C. 第三方插件向 stdout 打印诊断文本，会破坏扫描和宿主 JSON 协议。
修复：helper 启动时保存原 stdout 的私有、不可继承输出通道，再重定向插件可见的
OS stdout 与 C runtime fd 1 到空设备；仅宿主 JSON 使用私有通道，stderr 保持原有行为。
普通 Tauri 启动不重定向。不会靠跳过非 JSON 行掩盖问题，也不接受插件伪造的 JSON 行。
原生夹具分别通过 C puts、Rust stdout、Win32 WriteFile 输出噪声和 JSON 形文本：
旧协议测试失败；修复后扫描仅返回一个 JSON 对象，宿主返回四条正确请求响应。

D. VST2/VST3 修改混响或延迟参数后，导出可能沿用加载时的尾音长度。
修复：在停止处理的导出准备阶段刷新当前参数、latency 和 tail；启动探测后再刷新并
计算导出长度。保留同一插件实例、PDC 和 30 秒截断提示，实时处理不增加尾音属性轮询。
夹具覆盖首次处理后才报告尾音、仅尾音变化而延迟不变、无限尾音截断。

  - 真实插件手动脚本支持三种格式、au3: ID 与 shell 精确选择；原生窗口和参数测试需
    显式启用，未执行的检查记录 skipped。比较覆盖双声道与恢复后的完整帧数。

7. 第九轮：实时旁路与陈旧控制隔离（起点 6e95a33）

已加载且健康的插件可以原地切换旁路，保留 processor、参数和原生编辑器。
干声延迟线持续推进；旁路期间停止湿声处理，重新启用时清除冻结的 DSP 历史，
延迟预热阶段使用已对齐干声前缀。PDC 保持不变，处理线程更新 tail 与截断标记。
故障或正在恢复的图仍走重建；缺失实例重新启用仍执行实际加载并明确返回失败。

参数读写在排队前绑定目标身份；Undo、重新定位和会话替换不会让旧操作落到新实例。
正常捕获同一控制器的 state blob 不会错误地判为新状态意图。旁路、移除和排序在
捕获完成后按 slot ID 查找，不再使用过期数组下标；目标消失不写保存或历史。

验证：
  - 前端旧代码有 15 项新回归失败；修复后聚焦 61 项、全量 1102 项通过，3 项跳过。
  - 旧 helper 的旁路切换会改变 sessionId；修复后重复切换保留 ID、参数和 state。
  - Native audio 46 单测及 4 项原生 helper 集成回归通过。
  - 本地原生夹具子进程验证双声道、3 样本延迟、跨块预热前缀及恢复后的湿声增益，
    不打开原生窗口或声卡，不修改进程全局环境变量。
  - Linux x64、macOS ARM64/x64 完整原生宿主及测试代码交叉检查通过。
